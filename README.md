# ClinicCRM — прототип пути администратора

Доработанная копия публичного репозитория `Maksim1323/clinic-crm-proto`. Существующие цвета, стили и компоновка сохранены; новые элементы используют исходные классы. Доработки выполнены локально, в GitHub не отправлялись.

## Запуск

Из этой папки выполните `python -m http.server 8000`, затем откройте `http://localhost:8000/`. Также приложение может работать как статический сайт.

## Что проверять

1. В «Коммуникациях» выберите пациента и нажмите «Путь обращения».
2. Выберите причину передачи и примите обращение в работу. Задача появится в разделе «Задачи».
3. Укажите будущую дату и время. Это только согласование — запись в МИС не создаётся.
4. Отметьте ручную проверку в МИС и сохраните отметку. В демонстрации МИС не подключена, отметка не проверяется автоматически.
5. Создайте задачу на напоминание за 24 часа; сообщение автоматически не отправляется. При сроке, который уже прошёл, задача отображается просроченной.
6. Отметьте визит или неявку; создайте последующую задачу либо завершите обращение. Можно создать новое обращение, не стирая предыдущее.
7. Перезагрузите страницу: локальные обращения и задачи сохраняются в браузере.

В карточке можно создать задачу на передачу медицинского, финансового или организационного вопроса. Передача — только локальная запись, уведомление не отправляется. Демоданные и существующая аналитика являются вымышленными.

## Ограничения и безопасность

Это статический демонстрационный прототип, не готовая медицинская система. ИИ, телефония, мессенджеры, МИС, напоминания, фоновые задания и реальные отправки не подключены. Нет серверного хранения, разграничения доступа, аудита, резервного копирования и подтверждения юридического соответствия. Данные сохраняются в `localStorage` и доступны в браузере. **Не вводите настоящие персональные или медицинские данные.** Очистка данных браузера удалит результаты.

В репозиторий и скрипты не включены токены. Прототип не выполняет операций с GitHub.

## Проверка сценария

Демонстрационный smoke-тест `test-journey.cjs` использует Node.js и jsdom: `npm install --no-save --no-package-lock jsdom@26`. В отдельном терминале запустите `python -m http.server 8000`, затем `node test-journey.cjs`. Тест проверяет шаги, защиту от отсутствующего подтверждения, создание задачи, локальное восстановление и отсутствие базовых ошибок. Это не замена ручному тестированию в настоящих браузерах.
