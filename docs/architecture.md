# Структура и границы прототипа

- `index.html`, `css/`, `js/` — статический интерфейс. Файлы оставлены в корне намеренно: так не ломается существующий сайт GitHub Pages и сохранён его дизайн.
- `ident-amocrm-ai.html` — сохранённая старая самостоятельная страница; она не является точкой входа сервера и не участвует в новом Telegram-сценарии.
- `src/server.js` — запуск и привязка к `PORT` на `0.0.0.0`.
- `src/app.js` — HTTP-маршруты, обработка webhook и очередь тестовых действий. Это ещё не полноценная многопользовательская архитектура.
- `src/config.js` — чтение переменных окружения; значений секретов в репозитории нет.
- `src/integrations/` — HTTP-клиент и адаптеры Telegram, Gemini, GigaChat и OpenAI-совместимого API.
- `src/workflow/triage.js` — предварительные триггеры передачи и проверки текстовых ответов. Правила не гарантируют безопасность или клиническую корректность.
- `src/storage/json-store.js` — временное JSON-хранилище для одного процесса. По умолчанию файл расположен в `/tmp`; это **не** постоянная БД.
- `tests/` — тесты сценария администратора и API. Внешние API подменяются заглушками.
- `server.js` — совместимый переходник для старой команды `node server.js`.

Статический сайт GitHub Pages не запускает Node.js. Telegram и выбранный ИИ требуют отдельного Web Service, который обслуживает и интерфейс, и API с одного домена. Данные тестового Telegram не объединяются автоматически с карточками пациентов на статической странице.

Состояния диалога: `ai` → `waiting` (нужен человек) → `assigned` (человек взял диалог); возврат `assigned` → `ai` включается сотрудником. Фоновые задания выполняются одним процессом; прерванная или неподтверждённая отправка направляется сотруднику вместо автоматического повтора. Очередь и уведомления не являются промышленным решением.

На Render по умолчанию файловая система временная; на бесплатном сервисе файлы теряются при засыпании, рестарте и redeploy. Нет ролей, полноценного аудита и защищённого хранения. Для реальных пациентов проект не пригоден.
